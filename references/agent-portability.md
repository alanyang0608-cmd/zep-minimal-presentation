# 普通 agent 如何稳定执行

质量分为三层：**内容判断、确定性排版、实际视觉检查**。生成器固定第二层；第一层仍依赖材料与模型，第三层依赖浏览器/视觉能力。

## 能力分级

| 环境能力 | 执行方法 | 能承诺的范围 |
| --- | --- | --- |
| 读文件 + Python + 浏览器截图 | 读规范、写JSON、运行生成、逐页检查 | 可交付经过实际检查的演示 |
| 读文件 + Python，没有浏览器 | 生成并运行结构检查，交付HTML与检查清单 | 结构和数据约束通过；视觉待人工检查 |
| 只有文本输出 | 按契约输出JSON和运行命令，交给用户运行 | 内容草案；不能称为已经生成/验收 |
| 有原生PPT工具 | 将内容计划和设计规则映射到原生对象 | 根据该工具验证实际排版和动画；不沿用HTML验收结论 |

## 最小可靠流程

1. 阅读SKILL.md，先处理模板选择。用户未选且未授权代选时，展示五套中文选项与可用预览，等待选择；不得把示例主题当作用户选择。然后只读取所需的内容契约和设计预设说明。
2. 为每页写主张、证据、页型：独立观点用statement，章节用section，条目用rows，提问用dialogue，产品/作品可用单图gallery。不要把一整份指南自动拆成连续三栏；不要先开始自由写CSS。
3. 复制minimal.json，写入选定的theme，以纯文本填写。数值、来源与定义从用户材料中提取；缺失信息标注为待补，不虚构。新稿tone用auto，不重写颜色或运行样式；无执行能力时仅提供JSON和命令。
4. 运行`build.py --check`；按报错位置修复；阅读ADVICE编排提示并按实际材料判断，不把提示变成必须凑够的配额。目录引用使用语义ID，不使用不断变化的页码。
5. 生成HTML并用相同JSON运行`build.py deck.json --verify talk.html`；显式使用过`--theme`时，验证时传入相同值。然后打开，等待活动页idle再截图。按动效类型抽查过程，逐页看最终画面。
6. 如果密度不合适，先改内容分组/拆页。需要超出页型能力时在任务副本扩展，不改安装包内样例。
7. 修正后重新生成并再次verify；保存JSON、HTML及必要预览。报告版本、模板、执行环境、已测范围和限制；定制变体单独说明，不宣称标准模板验证通过。

## 自检运行环境

执行 `python3 scripts/check_portability.py`。该工具只复制生成器、运行样式和中性 JSON 到临时目录，以 `-I -S` 禁用用户路径和第三方包，从另一个工作目录生成五套 HTML 并验证逐字节一致。还检查未选模板时不会生成文件。

通过意味着具备执行能力的普通 agent 可以调用同一生成器；不代表不同模型已经实测通过，也不保证文字提炼质量相同。

## 示例评估任务

先检查选择交互：用户只说“用这个Skill做一份分享PPT”时，应先看到五套模板与选择问题，不应已经得到成稿。用户回复“3”后应使用midnight；一开始指定“荧光黄点阵”应直接使用acid-notes；用户只问“推荐哪种”时先推荐并等待选择，明确“你来选并直接做”才可代选。无需专门的多选控件，文字编号列表同样有效。

可用下面的非私有任务评估另一个agent，不给它本包示例的答案：

> 为一次8分钟的社区分享制作6–8页演示，主题是“怎样把读书记录变成行动”。材料包括三个原则、四个先后阶段和一个明确标注为演示的6/8完成比例。使用acid-notes。不要加外部图片或真实人物信息。需要目录跳转、至少一张静态展示页、可重播动效与讲者提示。

观察实际结果，而不是让模型自评分：材料是否完整；6/8是否正确显示75%；目录是否到正确目标；无外部依赖时能否打开；静态页是否保持静态；长文字是否溢出；是否明确区分演示数字和事实。若做模型对比，固定输入、环境和约束，保留产物与截图，不只比较文字评价。

## 可复现边界

- 相同JSON、主题、输入素材与未修改的工具包版本产生相同HTML字节，不需模型重新发明版式。`--verify`会重新生成并完整比对；只比颜色描述、元信息或截图不能证明一致。详见[配色一致性](color-consistency.md)。
- 字体、浏览器、窗口比例影响最终像素。需要严格复现时记录系统/浏览器/视口，并用已有授权字体；本包不内置字体。
- 内置工具没有模型SDK、隐式网络请求、知识库服务或私有插件绑定；所有素材和规范相对路径寻址。
- 生成器不替模型辨别事实、判断照片授权或理解所有复杂图表；输入契约和验收减少常见错误，不保证任意模型获得相同叙事质量。
